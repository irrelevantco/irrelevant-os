The next personal update adds a vertical pipeline and recoverable lead removal.

Pipeline stages now run top to bottom. The toolbar stays near the top while scrolling, with search by business/industry/location, a stage jump selector, and expand/collapse controls. Each stage shows 12 cards per page, so hundreds of Discovered leads no longer create an exceptionally long board or put the horizontal scrollbar out of reach. Up to 500 recent leads load; a visible notice directs larger pipelines to the searchable table.

Organization owners can right-click a pipeline card or lead-table row, use Shift+F10, or open its **…** action button and choose **Delete lead…**. The same action is on the detail page. A named confirmation moves the lead to **Trash**, removes it from active CRM queries and metrics, and cancels queued preparation, unaccepted preparation proposals and queued unsent delivery approvals. Notes, research, original business/source information, suppression entries and delivery/contact history remain in the database. **Leads → Trash** or **Pipeline → Trash** restores the previous stage and history without resuming cancelled work. This is recoverable removal, not permanent erasure. Members cannot remove, restore or list Trash; owner authorization is rechecked in the database.

Removal is blocked while preparation is running, an email is sending/uncertain, a future appointment exists, or a calendar outcome is syncing/uncertain. Stop preparation or resolve/cancel the relevant operation first; removal does not send a cancellation to Google. Stale confirmation requests fail without changing the lead. Removed business identities remain reserved, preventing accidental recreation through re-import. Opt-outs remain suppressed after restore.

**This update requires one additive database migration for Trash.** After updating the Windows app, keep Docker running and choose **Workspace → Update local database…**, confirm, then reload. Existing accounts, leads, notes, research, connections and private Google setup are preserved. The vertical pipeline can render before that migration; missing Trash RPCs show update instructions instead of silently losing a requested change. Hosted databases require applying the repository migration separately; the desktop tool only updates the supported existing local Docker stack.

Use **Workspace → Check for app updates…** in the installed Setup edition. Download and install/restart require your choice. Portable ZIP installations need the Setup edition once to use the standard updater. GitHub assigns the release version only after exact-commit checks, native Windows startup and update-cycle tests pass. No sending, scheduling, billing or hosted deployment is enabled by this release.

Local validation covers the actual 387-lead browser flow on desktop and mobile, search, vertical layout with no horizontal overflow, stage pagination/jumping, context menus, confirmation/cancellation, Trash/restore, preserved notes and live database counts. Database tests cover owner/member/anonymous and cross-organization permissions, stale/idempotent requests, queued-work cancellation, suppression and in-flight operation protection. Upgrade tests exercise an isolated old-schema database and verify existing fields remain unchanged. This remains an unsigned personal preview.
